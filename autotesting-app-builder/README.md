# 自动测试评分应用构建技能

本技能根据三份业务材料生成离线 Windows 评分应用：评分规程 PDF、人工填写的 Excel 评分表、带 `{{ }}` 可填位置的 Word 检验报告模板。它先建立单元格与规则的对应关系，再在项目副本中编写 Excel 公式，最后生成应用、报告映射和验证记录。Excel 原生计算是唯一的得分来源。

## 使用方法

1. 准备三份材料，并说明期望的项目名称与输出目录。
2. 在 Codex 中提出构建需求并使用本技能。Codex 会依据 `SKILL.md` 检查环境、解析材料和生成项目；环境要求见 `references/environment.md`。
3. 核对少数会改变得分或报告含义、且材料无法判定的问题。用户决定会写入项目记录。
4. 查看生成项目的 Excel 公式、报告字段、测试与审计结果，再使用完整的 Windows 应用文件夹。

## 整体流程

`检查环境 → 盘点三份材料 → 建立输入与评分映射 → 核对 PDF 规则 → 编写并用 Excel 验证公式 → 映射报告填充位置 → 生成应用 → 用已填工作簿回归测试 → 打包交付`

原始三份材料保持不变。报告只填充模板中已映射的可填位置，其他文字和格式不改动。需要复核的业务状态写在项目审计文件和应用界面，不写进检验报告。

## 到哪里找交付文件

生成项目通常位于工作空间的 `generated_apps/<项目名>/`。其中最常用的两个文件位于：

| 文件 | 典型位置 | 用途 |
| --- | --- | --- |
| Windows 程序 | `generated_apps/<项目名>/dist/<应用名>/<应用名>.exe` | 启动评分应用；运行时需要同目录下的配套文件。 |
| 已填公式评分表 | `generated_apps/<项目名>/templates/<评分表文件名>.xlsx` | Excel 评分模板；具体文件名以 `config/project.json` 的 `excel_output.template` 为准。 |

实际项目名称和文件名以生成项目为准。项目根目录的 `README.md` 会列出该项目的具体位置；评分表路径也记录在 `config/project.json` 的 `excel_output.template` 中。

`SKILL.md` 是执行规范；[Structure.md](Structure.md) 说明技能目录。每个子目录也有中文 `README.md` 与 `Structure.md`。
